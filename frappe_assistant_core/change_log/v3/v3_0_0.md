## Version 3.0.0

**The assistant moves inside your ERP.**

Until now, Frappe Assistant Core was a bridge: it exposed your Frappe data over
MCP so an external client like Claude Desktop could reach it. That path is
unchanged, still free, and still the default.

What's new is the other half — **FAC Chat**, a full assistant that lives inside
Frappe itself. A widget on every Desk page and a full-screen workspace at
`/copilot`, answering from your own records, inside your own permissions, with
every tool call written to the audit log.

And with **MCP Connect**, it is no longer limited to the tools we ship. Point it
at any MCP server — Slack, Linear, a second ERPNext instance — and the assistant
can work with those alongside your ERP data.

FAC Chat is **opt-in and ships disabled**. If you use FAC as an MCP server, this
release changes nothing about how you work.

---

### New Features

- **FAC Chat** — an in-Frappe assistant: a Desk widget and a `/copilot`
  workspace. It reads the screen you are on, so "this invoice" or "this
  customer" means what you would expect. It can draft and submit documents, run
  reports and update records, always behind a confirmation step. Enable it in
  **Assistant Core Settings → FAC Chat**, then `bench restart`. Powered by FAC
  Cloud; register at https://fac-suite.com.

- **MCP Connect — bring your own tools.** Connect external MCP servers from
  **FAC Chat → Settings → Connections**. Paste an endpoint and FAC checks the
  URL is well formed, that the server is reachable, and that it genuinely speaks
  MCP — then handles the sign-in for you, including OAuth dynamic client
  registration, so there is usually no client ID to create by hand. You see what
  the server exposes before anything is saved, and you allow or block individual
  tools per server; read-only tools are allowed by default.

- **Your FAC Connect endpoint, surfaced.** The MCP endpoint other clients use to
  reach this ERP now appears in chat settings, not only in the Desk admin page.

- **Workspace routing rules.** Route specific work to specific models. A new rule
  starts in **shadow mode** — matched and recorded, never applied — so you can
  see what it would have done before it does it. Every routed turn carries a
  receipt, shown as an exception-only chip in the SPA, widget and mobile.

- **Knowledge Base.** Upload the documents your business runs on — policies,
  SOPs, contracts — and ask questions against them. Answers cite the source
  document and section.

- **Agents and workflows.** Describe repetitive work in plain language and FAC
  builds an agent for it, runnable on a schedule or an event. Runs are inspectable
  node by node.

- **Support, in the product.** Raise a ticket from chat with screenshots or PDFs
  attached, read replies inline, and track everything under **My Tickets**.

- **Voice input** in both the SPA and the widget, and **expandable charts and
  diagrams** with PNG export.

### Security

- **Frappe permissions govern reads; writes to code DocTypes are hard-blocked.**
  Read access is now decided by Frappe's own permission model rather than a
  parallel list, and write attempts against code-bearing DocTypes (Server
  Script, Client Script and friends) are refused outright regardless of role.

- **FAC Chat runs inside your existing permission model.** It can only read what
  the signed-in user can already read, and every tool action is recorded in the
  Assistant Audit Log.

- Carries forward the 2.5.1 fixes, including admin-only publish and share for FAC
  Skills and its migration patch.

---

### Improvements

- **Credits are stated in plain terms.** Usage is expressed in credits with a
  sense of scale, and expiring credits are surfaced on their own rather than
  buried in a total. Raw token counts no longer appear on any user-facing surface.

- **An unpaid renewal is visible where you would look** — the billing hero, the
  Users page, the sidebar, and a Pay action on the specific owed invoice, all
  from one resolver so they cannot disagree. Adding a seat against a frozen
  billing cycle is now blocked with a stated reason instead of quoting a seat at
  0.00 that could not actually be bought.

- **Chat holds up under real use** — compose while a response streams, Stop that
  genuinely stops, Continue to resume a truncated answer, and pending approvals
  that survive a dropped connection.

- **Leaner tool schemas.** The six largest tool definitions were trimmed; one was
  53% of a 9,000-token block on its own. A budget test keeps them that way.

- **Mobile is a real surface** — drawer navigation, single-column chat, and
  reflowed list and settings pages rather than a narrowed desktop layout.

- **Settings reorganised** into Personal and Workspace groups, with an explicit
  unsaved-changes bar.

---

### Fixes

- **`list_documents` count and ordering** — the count query no longer fails on a
  scalar result, and the `order_by` sentinel is handled correctly.
- Carries forward the 2.5.1 correctness fixes: submittable DocTypes default to
  submitted-only, unresolved Link filter values are surfaced on zero-row results,
  and report filters are validated against each report's own declared contract.

---

### Breaking changes

- **The standalone FACO app is no longer used.** Chat now ships inside
  `frappe_assistant_core`. If you have the separate app installed, uninstall it
  after upgrading — running both will conflict.

- **Search is consolidated into one tool.** `search_doctype` and `search_link`
  have been removed; use **`search_documents`**, which routes on doctype and
  purpose. If you have saved prompts, skills or MCP client configurations naming
  either of the removed tools, update them. The two skills that documented them
  (`search-doctype-usage`, `search-link-usage`) are removed with them. The
  ChatGPT-compatible `search` and `fetch` tools are unaffected.

- **Minimum Python is now 3.10** (previously 3.8). Frappe v15 and later already
  require 3.10+, so most sites are unaffected.

---

### Upgrading

```bash
bench get-app frappe_assistant_core
bench --site <your-site> migrate
bench restart
```

Take a backup first, as you would for any major version.

**Requirements**

- Frappe v15 or v16
- Python 3.10+
- `assistant_runtime_sdk` 1.9.0, installed automatically from PyPI
- **Node 22+ is required only to build the FAC Chat SPA.** If you enable FAC Chat
  on a bench running an older Node, upgrade Node to 22 and re-run `bench build`.
  Sites using FAC purely as an MCP server do not need this.
- A FAC Cloud connection for chat — register at https://fac-suite.com

Four patches run on migrate: `recategorize_generate_document`,
`widen_credits_used_to_float`, `backfill_browser_diagnostics_default`, and
`backfill_workflow_trigger_docname`.
