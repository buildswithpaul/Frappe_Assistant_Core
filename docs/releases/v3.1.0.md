# Frappe Assistant Core 3.1.0

3.1.0 is a security release, and also the first feature release since 3.0.0. It
hardens the `run_python_code` sandbox and tightens who can use the data tools.
It also brings a large round of work on agents and workflows, FAC Chat and the
MCP tools.

**Upgrade promptly**, especially if `run_python_code` is enabled on your site.
Run `bench migrate` after updating. Two patches carry tool settings across.

---

## Upgrade notes

- **`run_python_code` and `run_database_query` require System Manager.** Until
  now any assistant-enabled user could call `run_python_code`. Users without
  the role no longer see either tool. FAC Tool Configuration cannot widen this.
- **`analyze_business_data` is removed.** It was unused. Use `run_python_code`
  instead.
- **`submit_document` is now `document_action`.** The old name still works as an
  alias for one more release. Update saved prompts, skills and MCP client configs.
  A migration patch moves the tool's FAC Tool Configuration settings to the new
  name.
- **`send_email` moved from the faco plugin to the core plugin.** If you had
  switched faco off, the patch keeps `send_email` disabled. You can enable it
  from FAC Admin.
- The pandas/numpy loaders (`pd.read_*`, `np.load` and similar) are no longer
  available inside `run_python_code`. Fetch data with `data_query`,
  `frappe.get_list` or `tools.*`. Code that read local files must change.

## Security

The `run_python_code` issue below is published as security advisory
[GHSA-659q-476f-pfm8](https://github.com/buildswithpaul/Frappe_Assistant_Core/security/advisories/GHSA-659q-476f-pfm8) (Critical, CVSS 9.9). It affects every release up to
and including 3.0.0.

### `run_python_code`

Code run by `run_python_code` executes in a sandbox. In 3.0.0 and earlier that
sandbox could be escaped. It has been reworked:

- Every read goes through a permission-checked, read-only `frappe` stand-in.
  Results respect role permissions and User Permissions for the calling user, and
  nothing can be written.
- Code is parsed and validated before it runs. A regular expression did this
  before. Imports, private and dunder attribute access, and the eval/exec family
  of builtins are rejected.
- The import hook uses an explicit allowlist with no exception for modules whose
  name starts with an underscore.
- pandas and numpy are exposed without their file, URL, SQL and pickle loaders,
  and without the functions that print host details. Everyday analysis
  (`pd.offsets`, `pd.api`, `np.ma`, `np.linalg`, `np.random`, …) is unchanged.
- The tool requires the System Manager role.

These are in-process restrictions. Running the code under OS-level isolation is
planned as a follow-up.

### `run_database_query`

- System Manager only.
- Frappe's internal tables (such as `__Auth`) are refused.
- File, lock and privilege statements (`INTO OUTFILE`, `LOAD DATA`, `GRANT`,
  `LOCK TABLES`, `FOR UPDATE`, `SET`, `CALL`, …) are refused. Validation uses a
  SQL lexer, so these keywords inside strings, comments and identifiers no
  longer cause false positives.
- Results are capped at 1000 rows, even when the query sets a higher `LIMIT`.

### Elsewhere

- **Workflow marketplace:** importing or editing workflows requires System
  Manager, and import is denied by default.
- **Site registration:** resending verification or changing the owner email of a
  pending site now requires the site's registration token.
- **FAC-Cloud-only tools:** the browser and document-rendering tools are offered
  only to FAC Cloud, not to other MCP clients.

## Agents and workflows

- **Builder:** tool and loop nodes, with config panels and checks that mark
  invalid nodes. A workflow names a runtime user, and nodes run and test as that
  user. Graph layout is clearer, and the system prompt opens in a large editor.
- **Safer activation:** activating a workflow warns about any write tool that is
  not set to run unattended. A setup checklist covers start, run-as user, write
  approvals and model.
- **Runs:** see skipped actions, timeouts, event-triggered runs and full errors.
  Copy, download or expand the output. A failed run keeps its partial output.
- **Triggers:** filters are kept on edit and shown. You can test a trigger on a
  real document, open the run a firing started, and runaway loops are capped at
  20 fires per trigger and document per hour. The cap is configurable with
  `fac_trigger_breaker_max_fires_per_hour`.
- **Templates:** a typed import form with required fields enforced, a summary of
  what a template needs and how it runs, and templates that create their own
  trigger on import.
- An FAC Cloud outage now shows as an outage with retry, not an empty list.

## FAC Chat

- **Thinking level:** choose from Off to Max. The receipt names the
  level used, and a failing hand-picked model opens the model picker.
- **Files:** the model sees every file attached in the conversation on every
  turn. A send waits for its uploads, attachments survive a reload, and two
  files with the same name both show.
- **Stop and Continue:** Stop is honoured however early it is pressed, and never
  overwrites text that was already saved. Continue appends to the turn instead of
  replacing it.
- **Desk widget:** rebuilt on FAC Chat's own components. Outage and announcement
  banners show inside the panel, and typing in it no longer triggers Desk
  keyboard shortcuts.
- **Quota and billing:** quota prompts are now cards and a launcher dot, not
  dialogs over Desk. Admins are offered plans and credits, and members are asked
  to contact their admin. The payment tab shows why the last payment failed. The
  billing form offers every country, UPI Autopay is offered only in India, and
  the plan refreshes after checkout.
- **Onboarding:** email verification resumes instead of asking you to reconnect,
  and a dead verification link says so and offers a new one.
- **Privacy:** every user receives the workspace's memory-consent policy, and
  the first-run consent switch starts off unless the workspace is Opt-Out.
- `/chat?prompt=…` pre-fills a new chat without sending it.

## MCP tools

- **`document_action`** replaces `submit_document` and can also cancel and amend.
- **`list_documents`:** pages with `offset` and `next_offset`, pages never
  overlap, and the count works on Frappe v16.
- **`generate_report`:** `max_rows` and `summary_only` bound large reports, and
  the response includes `total_count`. A prepared report that is still running
  is reused, and one that completes with zero rows is returned instead of being
  treated as unfinished and queued again.
- **`attach_chat_file`** attaches a chat upload to a document.
- **Writes:** Table MultiSelect rows are written, child DocTypes are routed via
  their parent, and `document_action` and `create_document` stay atomic inside
  workflows. Every write tool says why a permission was denied, and a non-admin
  user can create their own ToDo.
- **`run_python_code`:** imports of pre-loaded modules now bind their names, so
  `from collections import Counter` and `from datetime import datetime` work.
  `collections`, `itertools`, `functools`, `heapq`, `bisect`, `copy` and
  `string` are available. Printed output is kept when the code fails.
- **Performance:** the tool registry is built in one pass, and skipped entirely
  for methods that never read it.

## Skills

- Six system skills let the assistant audit and configure an ERPNext site
  through conversation, among them `site-health-check` (read-only, reported by
  severity) and `guided-setup`. They share a plan → confirm → validate → write
  protocol.
- The Claude skill-export template is retired.
